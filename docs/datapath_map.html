Where the register addresses come from

The register file reads straight out of the instruction word. Slice the same bits for every instruction type. The controller decides whether those bits mean anything for the current instruction.

Build it in this order

  1. Write the port list and declare the 7 internal wires: pcnext pcplus4 pctarget immext srca srcb result. Check: iverilog -Wall compiles the empty module with no errors.
  2. Close the next-PC loop: pcreg, pcadd4, pcaddbranch, pcmux. Check: in a small testbench with pcsrc = 0, pc reads 0, 4, 8, 12 after reset.
  3. Add rf and ext, slicing instr as shown above. Check: feed a known instr and confirm a1, a2 and a3 hold the right register numbers in the waveform.
  4. Add srcbmux and alu. Check: preload two registers and confirm aluresult matches for both alusrc values.
  5. Add resultmux and wire result back to wd3. Check: with regwrite = 1, the register file gets written on the next rising edge.

Easy mistakes

  • writedata is rd2 itself, tapped before srcbmux. If you take it from srcb, every sw stores the address offset.
  • pctarget is pc + immext, not pcplus4 + immext. Branch offsets are relative to the branch instruction.
  • Use your own port names when you instantiate: alu uses F and out, flopr uses rst, and regfile uses we.
  • resultmux assumes mux3 takes a 2-bit sel with 00, 01, 10. Your current file has separate sel0/sel1 bits and four inputs, so fix that first.
  • A wire you forget to declare becomes an implicit 1-bit net in Verilog. Put `default_nettype none at the top of the file and that turns into a compile error.
