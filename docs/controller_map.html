RV32I Controller Map

The controller reads three fields of the instruction and the ALU's zero flag, and produces every control signal the datapath needs. It has no clock and no state: each output depends only on the current inputs. Pick an instruction to see what each signal should be.

Subtract only when both op5 and funct7b5 are 1. Without the op5 check, addi with a negative immediate would be decoded as a subtract, because instr[30] is an immediate bit there. Click addi above to see it.

How to lay out the code

Split it the way the diagram is split: two small decoders, plus one line in controller.v that joins them. Give each module its own file: sim.sh finds a module by looking for a file with the same name, so a controller_tb could test aludec on its own.

datapath/controller.v 
module controller (
    input  [6:0] op,
    input  [2:0] funct3,
    input        funct7b5, zero,
    output [1:0] resultsrc,
    output       memwrite, pcsrc,
    output       alusrc, regwrite,
    output [2:0] immsrc, aluctrl
);
    wire [1:0] aluop;
    wire       branch, jump;

    // maindec md (...);
    // aludec  ad (...);
    // assign pcsrc = ...;
endmodule
datapath/maindec.v 
module maindec (
    input  [6:0] op,
    output [1:0] resultsrc,
    output       memwrite, branch,
    output       alusrc, regwrite, jump,
    output [2:0] immsrc,
    output [1:0] aluop
);
    // One 12-bit bus, one row per case.
    // Order = column order of the table.
    reg [11:0] controls;
    assign {regwrite, immsrc, alusrc,
            memwrite, resultsrc, branch,
            aluop, jump} = controls;

    // always @(*) case (op) ... endcase
endmodule
datapath/aludec.v 
module aludec (
    input        op5,
    input  [2:0] funct3,
    input        funct7b5,
    input  [1:0] aluop,
    output reg [2:0] aluctrl
);
    wire rtypesub = op5 & funct7b5;

    // always @(*)
    //   case (aluop)
    //     2'b00: ...
    //     2'b01: ...
    //     default: case (funct3) ...
endmodule

The 12-bit controls bus is 1 + 3 + 1 + 1 + 2 + 1 + 2 + 1 bits, matching the table columns left to right. Each table row then becomes one line, for example 7'b0000011: controls = 12'b1_000_1_0_01_0_00_0; // lw.

Things that trip people up

  • No clk or rst. Your current controller.v has them. A single-cycle controller has no state, so remove them.
  • Every case needs a default. Without one, an always @(*) block infers a latch. Defaulting to all x makes an unsupported opcode stand out in GTKWave.
  • Don't cares. Writing x for don't cares lets synthesis simplify the logic. Writing 0 also works. It only matters that the 1s and real values are right.
  • beq works through subtraction. aluctrl = 001 makes the ALU compute rs1 − rs2, so zero is 1 exactly when they're equal.
  • memwrite skips the datapath. It goes from the controller straight to dmem in the top level, which is why datapath.v has no memwrite port.

To test it on its own: write datapath/controller_tb.v that sets op, funct3 and funct7b5 for each instruction in the picker, compares the outputs with the tables, and prints any mismatch. Run it with ./sim.sh datapath/controller_tb.v.
