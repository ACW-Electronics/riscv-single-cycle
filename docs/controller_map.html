RV32I Controller Map

The controller reads three fields of the instruction and the ALU's four flags, and produces every control signal the datapath needs. It has no clock and no state: each output depends only on the current inputs. Pick an instruction to see what each signal should be.

Inside aludec

Follows the picker above. The low 3 bits of aluctrl are funct3 itself, so the only logic is the alt bit (bit 3) and a 3-way choice on aluop.

Main decoder: op → 15 bits

One row per opcode. This becomes one case (op) where each branch assigns a whole row. Blue columns stay inside the controller.

ALU decoder: → aluctrl

Outer case (aluop). For 10, aluctrl = {alt, funct3}, so no 8-way table is needed. Outputs use the 4-bit F codes in alu.v.

Branch condition: funct3 + flags → taken

Every branch runs the ALU as rs1 − rs2 (aluop = 01), so the flags describe that subtraction. taken only matters when branch = 1.

How to lay out the code

Split it the way the diagram is split: two small decoders, plus one line in controller.v that joins them. Give each module its own file: sim.sh finds a module by looking for a file with the same name, so a controller_tb could test aludec on its own.

datapath/controller.v 
module controller (
    input  [6:0] op,
    input  [2:0] funct3,
    input        funct7b5,
    input        zero, negative,
    input        overflow, carry,
    output       regwrite, memwrite,
    output       alusrcb,
    output [1:0] alusrca, resultsrc,
    output [1:0] pcsrc,
    output [2:0] immsrc,
    output [3:0] aluctrl
);
    wire [1:0] aluop;
    wire       branch, jump, jalr;
    reg        taken;

    // maindec md (...);
    // aludec  ad (...);
    // always @(*) case (funct3) ... taken
    // assign pcsrc = ...;  jalr first
endmodule
datapath/maindec.v 
module maindec (
    input  [6:0] op,
    output       regwrite, memwrite,
    output       alusrcb, branch,
    output       jump, jalr,
    output [1:0] alusrca, resultsrc,
    output [2:0] immsrc,
    output [1:0] aluop
);
    // One 15-bit bus, one row per case.
    // Order = column order of the table.
    reg [14:0] controls;
    assign {regwrite, immsrc, alusrca,
            alusrcb, memwrite, resultsrc,
            branch, aluop, jump, jalr}
            = controls;

    // always @(*) case (op) ... endcase
endmodule
datapath/aludec.v 
module aludec (
    input        op5,
    input  [2:0] funct3,
    input        funct7b5,
    input  [1:0] aluop,
    output reg [3:0] aluctrl
);
    wire rtypesub = op5 & funct7b5;
    // alt: rtypesub if funct3 = 000,
    //      funct7b5 if funct3 = 101, else 0

    // always @(*)
    //   case (aluop)
    //     2'b00: ...  add
    //     2'b01: ...  sub
    //     2'b10: ...  {alt, funct3}
    //     default: ...
endmodule

The 15-bit controls bus is 1 + 3 + 2 + 1 + 1 + 2 + 1 + 2 + 1 + 1 bits, matching the table columns left to right. Each table row then becomes one line, for example 7'b0000011: controls = 15'b1_000_00_1_0_01_0_00_0_0; // lw. Your maindec.v assigns each signal separately instead, which works just as well.

Things that trip people up

  • No clk or rst. A single-cycle controller has no state. Every output depends only on the current inputs.
  • taken means nothing outside a branch. For other opcodes, funct3 encodes something else and the flags come from whatever the ALU did. That's why pcsrc only uses it as branch & taken.
  • Every case needs a default. Without one, an always @(*) block infers a latch. Defaulting to all x makes an unsupported opcode stand out in GTKWave.
  • Don't cares. Writing x for don't cares lets synthesis simplify the logic. Writing 0 also works. It only matters that the 1s and real values are right.
  • Branches work through subtraction. aluctrl = 1000 makes the ALU compute rs1 − rs2, and the flags of that subtraction decide all six branches.
  • memwrite skips the datapath. It goes from the controller straight to dmem in the top level, which is why datapath.v has no memwrite port.

To test it on its own: write datapath/controller_tb.v that sets op, funct3 and funct7b5 for each instruction in the picker, compares the outputs with the tables, and prints any mismatch. Run it with ./sim.sh datapath/controller_tb.v.
